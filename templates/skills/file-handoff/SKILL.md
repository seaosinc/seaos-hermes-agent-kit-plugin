# ファイルを受け取る・返す

## 返すだけの依頼は、自分の返事で返す

「この画像を DM で送って」「さっきのファイルをここに貼って」のように、**手元にある
ものをユーザーへ返すだけ**なら、その場で返す。
**Slack へ投稿できるのは窓口だけ**で、カードにすると送る手が無いまま止まる。

返事の本文に1行ずつ書くと、ゲートウェイが添付して送る:

    MEDIA:<ファイルの絶対パス>

返してよいのは、**このユーザーから受け取ったファイル**（注記に出たパス）と、
**カードの成果物**の2つである。それ以外を送ってと頼まれたら、送れないと答える
（ここは断ること自体が目的である）。

送り先は**いま話している相手**に限る。別の人やチャンネルへ送ってと言われたら、
**送れないと答えて、ユーザーに自分で転送してもらう。** カードにしても、
誰も Slack へ投稿できないので止まるだけである。

## 受け取ったファイルは、置き場へ写してパスを本文に書く

ユーザーが Slack でファイルや画像を送ると、メッセージの頭に
`[The user sent a document: '…'. It is saved at: <パス>]` のような注記が付く。
**そのパスは窓口にしか見えない**（別のプロファイルや使い捨ての部屋の中からは届かない）。
しかも一日ほどで消える。

依頼にファイルが関わるなら、カードを作る前に写す:

    seaos-kit files keep <パス> [<パス> ...]

出てきたパス（1行に1つ）を、**本文にそのまま**次の形で入れる。
Excel・Word・PowerPoint・PDF は、隣に Markdown へ変換したもの（`….xlsx.md`）も出る。
**それも行に含める**——そちらしか読めない場合がある。

    添付ファイル（このパスから読める。読み取り専用）:
    - <出てきたパス>  … 何のファイルか一言

**何のファイルかを一言添える。** 分解されると本文は子カードへ書き直されるので、
どれを読むべきかを decomposer が判断できる必要がある。

**写すのは、依頼に関わるファイルで、注記に出たパスだけである**（挨拶に添えた画像などは
そのままにする）。置き場の外を指定されたら断る——`seaos-kit files keep` 自体も断る。
