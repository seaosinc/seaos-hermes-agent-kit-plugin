# この作業部屋について

あなたは Hermes の担当から呼ばれて、使い捨てのコンテナの中で動いている。
**部屋の性質を知らずに動くと無駄に詰まる**ので、先に把握しておくこと。

## 承認する人はいない

**この部屋には人がいない。** 確認を求めて止まると、誰も答えないままタイムアウトで
落ちる。判断が要るところは**自分で決めて進み、決めた理由を最後の報告に書く**。

ただし**根拠が無いまま埋めないこと。** 判断に足る情報が無いのに進むと、もっともらしい
値をでっち上げて「直しました」と報告することになる——**呼び出し側はそれを信じる。**

情報が足りないときは、**何も変更せず**、次の1行だけを出力して終わる。

```
NEEDS-INPUT: <何が足りないか>
```

呼び出し側はこの印を見て、人に確認を取る。**あなたが待つ必要はない。**
「進めると壊れるとき」（範囲外のファイルを消す、依存を勝手に足す、既存の API を変える）も
同じ形で返すこと。

## 道具の足し方

**`apt-get` は通らない。** この部屋は権限を落として動いている（`--cap-drop ALL`）。
システムパッケージは足せない。

言語やツールが要るときは `mise` を使う。

```bash
mise use -g node@22        # 入れて PATH に通す
mise install               # リポジトリの .tool-versions / mise.toml を読んで入れる
```

入り先は `/cache` なので、**次の仕事でも残る**。リポジトリが版を宣言しているなら、
`mise install` を先に叩けば揃う。

## 消えるものと残るもの

| 場所 | 運命 |
|---|---|
| `/workspace` | **部屋と一緒に消える。** 作業はここでやる |
| `/cache` | **残る。** 言語本体と、落としたパッケージが入る |

`/cache` を消さないこと。**次の仕事が遅くなる。**

パッケージマネージャのキャッシュは環境変数で `/cache` に向けてある
（`npm` `pip` `uv` `go` `cargo` `maven` `gradle`）。**そのまま使えばよい。**

## ネットワーク

外には出られる。**組織の傍受プロキシが挟まっている**ので、証明書の検証は
システムの束（`SSL_CERT_FILE` ほか）に向けてある。**自分で `NODE_TLS_REJECT_UNAUTHORIZED=0`
のような無効化をしないこと。**

## 出力の置き場

**指示された相対パスに出す。** リポジトリの外（`/workspace` 直下や `$HOME`）へは書かない。
スクリーンショットやレポートは、呼び出し側が指定した場所に置けばよい——
**そこから先の受け渡しは担当がやる。**

## 触ってよい範囲

**指示されたリポジトリの中だけ。** 他のディレクトリ、Hermes の設定、`/cache` の中身は
対象外である。コミットと push は担当が行うので、**変更を残すところまでが仕事。**
